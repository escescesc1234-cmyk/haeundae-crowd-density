# 부산 해수욕장 AI 안전 관리 — 초기 알고리즘 흐름도

**설계 관점**: 컴퓨터 비전, 객체 탐지·추적, 군중 밀집도, 시계열 예측, 해양 안전, 모바일 앱  
**설계 수준**: AI 기본 원리를 아는 중학생도 흐름을 설명하고 구현 방향을 잡을 수 있는 수준  
**역할 경계**: AI는 사고 **발생을 확정하지 않는다**. 위험 **가능성**과 **근거**를 주고, 구조·통제 등 중요 결정은 **관리자가 현장 확인 후** 한다.

**현재 WaveGuard(광안리) 구현 참고**: 운영·지도·SK 보조는 **중앙 구역 1개**(`GWANGALLI-ZONE-CENTER`) 기준. 아래 흐름도의 「여러 구역」은 설계 전체 그림이며, 단일 구역으로 축소해도 3~11단계 논리는 동일하다.

## 핵심 판단 원칙 (한 줄 요약)

1. CCTV로 **사람 탐지**
2. **익명 번호**로 이동 추적
3. **구역별 인원수** 계산
4. **인원수 ÷ 면적**으로 밀집도 계산
5. **이동 방향·정체** 분석
6. **날씨·파도·조류** 정보 결합
7. **안전·혼잡·위험** 단계 판정
8. **관광객**에게 안전 정보 제공
9. **관리자 확인** 후 현장 대응
10. **결과 기록**하여 AI 개선

## 중학생용 구현 방향 체크리스트

| 단계 | 무엇을 만들면 되나? | 지금 프로젝트에 있는 것 |
|------|---------------------|-------------------------|
| 1 구역 설정 | 구역 ID, 이름, 면적 JSON | `config/zones.gwangalli.json` (중앙 1구역) |
| 2 데이터 수집 | API·시각 기록 | 기상청, SK(보조), 수동 입력 |
| 4~7 비전·인원 | AI 모델 + 추적 (또는 수동 인원) | 수동·테스트 입력 (`/api/analyze/manual`) |
| 8~11 밀도·등급 | 나눗셈 + 기준표 | `src/density/*` |
| 12 지속 확인 | 몇 초 이상 유지할지 | 히스테리시스·최소 지속 시간 |
| 13 예측 | 과거·날씨 가중치 | `src/forecast/*` |
| 14~15 앱 | 관광객·관리자 화면 | `public/tourist.html`, `admin.html`, WaveGuard |
| 16 개선 | 오경보 기록 | 알림 API, 관리자 확인 |

상세 개발자 명세는 [ALGORITHM.md](../ALGORITHM.md)를 참고한다.

## 윤리 한 줄

AI는 **「사고가 났다」**고 말하지 않는다. **「지금 이 구역은 위험해질 수 있으니 이쪽으로 가세요」**처럼 돕고, 방송·구조·통제는 **사람(관리자)**이 결정한다.
